Courier Tracking API demo

Plain page mirroring docs/api-examples.md, success cases only. Start the application with make run and open http://localhost:8080/demo.html. Each step shows its expected status; a green bar means the response matched it.

A fresh ID keeps each walkthrough independent; reusing an ID never resets its distance.

Custom location

Click the map to pick lat/lng (drag the marker to adjust). Store buttons fill the exact store coordinates and center the map there; the circles are the 100 m entry areas. Locations sent from this form are drawn as a path.

The browser cannot produce Kafka records. Produce from a terminal with the commands below (copy buttons),
then verify consumption through the HTTP API from this page. Requires make run: PostgreSQL, the
Compose broker, and the application with the local profile, which enables the Kafka ingress.


 
  Fixed sample courier used by scripts/kafka/sample-locations.jsonl.




  
K1. Register the sample courier POST /api/v1/couriers · expected 201 (409 if already registered)

  
Kafka carries no registration message, so the courier must exist before messages are consumed. make kafka-send does this step itself.

  

  






  
K2. Produce the sample messages terminal

  
Registers kafka-courier-1 and produces three key|json lines: Ataşehir at 12:00:00, Novada at 12:01:00, Ataşehir again at 12:01:30. Same scenario as HTTP steps 4, 5 and 5b.

  
make kafka-send

K3. Verify consumption GET /api/v1/couriers/distance · expected 200

  
On a fresh database the total after K2 is 1963.3136870424555 m and courier_store_visits holds three rows: Ataşehir closed at 12:01:00, Novada closed at 12:01:30, Ataşehir open.
  A second make kafka-send is a duplicate no-op: the total does not change and no record is skipped.

  

     

  






  
K4. Produce invalid messages and watch them being skipped terminal

  
Three records that cannot succeed on retry: malformed JSON, latitude 95, and an unregistered courier.
  The application skips each one without retrying and logs a single INFO line
  (Skipped unprocessable location message topic=… partition=… offset=… key=… exception=…) in the
  make run terminal; no rows are written. Afterwards K3 shows an unchanged total.
  Publishing skipped records to a dead-letter topic is the planned next step.

  
make kafka-send-invalid
